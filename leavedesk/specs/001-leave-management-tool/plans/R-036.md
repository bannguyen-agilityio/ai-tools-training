# Plan 17: R36 deputy HR admin

Phase P1. Depends on: 13 (approvals), 07 (employees). Blocks: none.

## Requirements and acceptance criteria

- **R36**: HR assigns the deputy role to one named active employee (audited, at most one at a time); an HR user's own leave is assigned to the deputy and the HR user cannot approve it; when HR is away the deputy decides managers' requests, audit shows the deputy as actor; the deputy has no access to employee, team, holiday, balance administration or exports.

Endpoints #22 (`GET/PUT /hr/deputy`). Completes routing `queue=deputy` that plan 10 refused.

## Files

Create: `app/modules/deputy/{router,service,repository,schemas}.py`; frontend HR Settings "Deputy" panel; `tests/deputy/*`, `tests/authz/test_deputy_403_matrix.py`.
Modify: `requests/routing.py` (HR admin → `queue=deputy`, `assigned_to=deputy`), `approvals/authz.py` (HR approver = HR admin or deputy; exclude requester), `approvals/service.py` list for deputy, `identity` dependency `require_hr_admin`.
Delete: none.

## Steps

1. Tests first: one-deputy invariant, 403 matrix over every `/hr/` route for deputy, self-approval.
2. PUT deputy: validates active employee, not role `hr`; swaps atomically (the partial unique index enforces one); audit as role change.
3. Routing for HR admin's own requests.
4. Approver authz updated; deputy sees queue `hr` and `deputy` items; HR admin sees `hr` items but not own.
5. Audit actor = deputy for decisions.
6. Settings UI.

## Risks and dependencies

- A-10: who approves the *deputy's* own leave; what if no deputy is set (HR admin's request has nowhere to go: refuse creation with a clear message?).
- A-3: intent still says "1 HR" in one place; correct the intent text.
- Single HR admin who is also the only HR approver when away: there is no cover beyond the deputy.
- Regression risk: every `/hr/` route must reject the deputy; matrix test must be generated from the route table so new routes are covered automatically.
