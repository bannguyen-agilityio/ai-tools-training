# Plan 13: R18 approve, R19 reject with reason, R22 unauthorised approver

Phase P1. Depends on: 10. Blocks: 14, 15, 17, 18, 20, 21.

## Requirements and acceptance criteria

- **R18**: direct manager approves Pending → Approved, reserved → used, employee emailed; two simultaneous approvers → exactly one succeeds, the other sees "This request was already decided."
- **R19**: reject with empty/whitespace reason refused inline; 1–500 chars → Rejected, days released, employee emailed with the reason.
- **R22**: a manager who is not the direct manager and not using cover calling approve → 403 and attempt logged.
- R17 remainder: nobody approves their own request, whatever the role (403; DB CHECK `decided_by <> employee_id`).

Endpoints #13 (`GET /approvals?scope=assigned`), #14, #15. The `scope=cover` and `on_behalf_of` parts are plan 14; HR-queue deciders (HR approver) logic is included for `assigned` with HR approver, and deputy-specific cases are plan 17.

## Steps

1. Tests first: full role matrix × endpoint, concurrency, reason validation, self-approval, redaction.
2. `can_decide` in the service layer (never only in the router).
3. Approve: guarded update with `version`/`status='pending'`; day rows stay active; audit; outbox + notification to employee (no Sick type).
4. Reject: validate trimmed reason 1–500; set `decision_reason`; day rows `is_active=false`; audit without the reason text; email includes reason to the employee only.
5. Unauthorised attempt: 403 and an audit/log entry (action `approve_denied`, ids only).
6. Approvals list for assigned items with redaction.
7. UI: list, detail (dates, warning, note while deciding), approve button, reject form with inline error and focus.

## Risks and dependencies

- A-5: R22 wording and 403-vs-404 choice; A-13: "while deciding" scope; A-14 recipients.
- Rejection reasons must never reach audit/logs/notifications bodies of others — test all sinks.
- Optimistic-lock error message exactly "This request was already decided."
- Requests with `queue=hr`: which HR approver may decide and the self-exclusion rule.
