# Plan 04: R1 login, R2 account protection, R3 invite and reset

Phase P1. Depends on: 01 (session, CSRF, audit), 02 (UI primitives), 03 (EmailSender/outbox). Blocks: every authenticated feature.

## Requirements and acceptance criteria

- **R1**: valid credentials → session cookie → Dashboard; non-`@asnet.com.vn` account rejected at create/invite; wrong email or password → identical "Email or password is incorrect" and no timing difference.
- **R2**: 5 failures/15 min per email → 6th refused 15 min regardless of password, logged, plus per-IP limit; password ≥ 12 chars, not common, Argon2id only; 8 h idle / 24 h max session; all sessions invalidated on password change; SPA on 401 clears state and returns to the sign-in page, keeping the target page.
- **R3**: invite link 48 h single use, HR never sees password/link; forgot-password response identical for any email, reset link 1 h; tokens hashed; expired/used link shows message and way to request a new one.

Endpoints #1–#7 (`login`, `logout`, `invite/accept`, `reset/request`, `reset/confirm`, `password/change`, `GET /me`). HR "create employee" and "re-send invite" endpoints belong to plan 07; this plan exposes `issue_invite(employee_id)` as a service they call.

## Files

Create: `app/modules/auth/{router,service,repository,models,schemas,dependencies}.py`; `app/modules/auth/passwords.py` (argon2-cffi, common-password list, length check); `app/modules/auth/tokens.py` (`secrets`, sha256 storage); `app/modules/auth/ratelimit.py`; migrations for `user_identity`, `one_time_token`, `login_attempt`; `app/jobs/purge.py`; email templates `invite`, `reset` (from plan 03 framework); frontend `src/features/auth/{SignIn,SetPassword,ForgotPassword,ResetPassword,ChangePassword}.tsx`, `AuthProvider`, `RequireAuth`; `tests/auth/*`.
Modify: `app/modules/identity/dependencies.py` (session creation/rotation), `src/api/client.ts` (401 flow), CI (daily purge workflow).
Delete: none.

## Steps

1. Write tests first: enumeration/timing, lockout, token expiry/replay, session expiry, invalidation, CSRF on login-protected routes.
2. Tables and migration.
3. Password policy and Argon2id (`verify` against a dummy hash for unknown emails to equalise time).
4. Login: rate-limit check → verify → rotate session (new token, no fixation) → set cookie `HttpOnly; Secure; SameSite=Lax`; audit success/failure (no email in free text beyond hash).
5. Session sliding expiry and max age; purge job.
6. Invite issue/accept; reset request/confirm; "issue new token voids previous".
7. Change password invalidates other sessions.
8. `/me` returns profile, role, deputy flag, team, CSRF token.
9. SPA pages and 401 return-path handling.
10. Run `security-review` on this module before go-live (CLAUDE.md gate).

## Risks and dependencies

- Largest security risk in the project (C-18); no custom crypto.
- A-6: per-IP threshold and trusted-proxy IP header unspecified; wrong choice either locks out the office NAT or disables the limit.
- A-25: `Secure` cookie on local HTTP.
- Email delivery failure blocks all new users (C-17): bell is no fallback for unauthenticated users.
- Common-password list source/licence undefined.
