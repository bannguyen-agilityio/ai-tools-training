# Plan 06: R6 working-day calculation + R11 public holidays

Phase P1. Depends on: 01, 02, 04 (HR session). Blocks: 09, 10.

## Requirements and acceptance criteria

- **R6**: Fri 6 Nov → Mon 9 Nov = 2; weekday holidays excluded; cross-year request counted and deducted per leave year; range with no working days refused with "This range has no working days."
- **R11**: Vietnamese 2026–2027 holidays preloaded (incl. compensatory days); HR add/edit/delete is audited and shows how many Pending/Approved requests it touches.

Endpoints #27 (`GET /holidays`), #28 (`POST/PATCH/DELETE /hr/holidays`), #29 (`GET /hr/holidays/impact`). This plan also creates the `leave_request` and `leave_request_day` tables (migration only, no request endpoints) so the impact query and day-expansion are testable now; plan 10 owns request creation.

## Files

Create: `app/modules/holidays/{models,repository,service,schemas,router,dependencies}.py`; `app/modules/leave_days/calendar.py` (pure: `expand_days(start, start_part, end, end_part, holidays) -> list[(date, slot, leave_year)]`, `working_days`); seed migration with Appendix A data; migration for `leave_request`, `leave_request_day` with all CHECKs and the partial unique index; frontend `src/features/hr/holidays/*`; `tests/leave_days/*`, `tests/holidays/*`.
Modify: none. Delete: none.

## Steps

1. Tests first: day-expansion table (Fri→Mon, holiday inside, holiday on weekend, half-day starts/ends, 31 Dec→2 Jan, zero-day range).
2. Pure `expand_days` using `COMPANY_TZ` dates only.
3. `public_holiday` table and seed (Appendix A, flagged unverified).
4. `leave_request` / `leave_request_day` migration per §5.1–5.2, including partial unique index; grants.
5. Holiday CRUD with audit (before/after) and delete confirmation.
6. Impact query: count of Pending/Approved requests whose active day rows include the date; returned by #29 and in the #28 response as `affected_requests`.
7. HR Holidays screen: year list, add/edit, "N requests affected", confirm delete with default focus "Keep".

## Risks and dependencies

- A-19: seed list is unverified; verification is due 30 Oct. Wrong dates silently wrong day counts. Treat the verified list as a go-live gate.
- Holiday edits must never rewrite `working_days` or day rows (C-8): test it.
- Day-row shape (two half-day rows per full day) is a modelling choice other plans rely on; review before merge.
