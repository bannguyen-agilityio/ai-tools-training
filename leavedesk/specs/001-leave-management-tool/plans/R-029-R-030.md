# Plan 01: R29 API security baseline + R30 audit log (backend foundation)

Phase P1. Depends on: C-16/Q5 gate. Blocks: everything else.

## Requirements and acceptance criteria

- **R29**: (a) no/invalid session → 401 except login/invite/reset; (b) every body validated by strict schema, unknown fields refused, parameterised queries; (c) state-changing call without valid `X-CSRF-Token` or with foreign `Origin` → 403; strict CSP; (d) security headers (CSP, `X-Content-Type-Options`, `Referrer-Policy`, HSTS), no stack traces in errors.
- **R30**: append-only audit record (actor, `acting_for_id`, action, target, time, before/after, ip) for create/approve/reject/cancel/balance/holiday/employee/login failure/role change/export; never stores passwords, tokens, notes, rejection reasons or Sick type in free text; application logs follow the same rule.
- Supports C-18: RLS on every table with no policies; test proves the anon key reads nothing.

This plan also carries the scaffold the other plans need (no R-number of its own): app factory, config, DB session, Alembic, CI, `/healthz`.

## Files

Create: `pyproject.toml`; `app/main.py`; `app/core/{config,db,errors,security_headers,csrf,logging,deps}.py`; `app/modules/audit/{models,service,repository,schemas,router}.py`; `app/modules/identity/{models,dependencies}.py` (employee, team, session tables + `get_current_user`); `migrations/` with first revision (employee, team, session, audit_log, RLS on all, app-role grants: no UPDATE/DELETE/TRUNCATE on `audit_log`); `tests/{conftest.py,test_security_baseline.py,test_audit.py,test_rls_anon.py,test_log_redaction.py}`; `.github/workflows/ci.yml`; `.env.example`.
Modify: none (greenfield). Delete: none.

## Steps (in order)

1. Write failing tests first: 401 matrix, CSRF/Origin, header presence, unknown-field refusal, problem+json shape, audit append-only, anon-key read test, log-redaction test.
2. Scaffold app factory, settings (`COMPANY_TZ`, `EMAIL_BACKEND`, DB URL from env), SQLAlchemy 2 session, Alembic.
3. Migration: `employee`, `team`, `session`, `audit_log` per §5.1; `CITEXT`; email domain CHECK; deputy partial unique index; RLS enabled, no policies; grants for app role.
4. `problem+json` handlers (400/401/403/404/409/422/429), generic 500 without trace.
5. Middleware: security headers; CSRF + `Origin` check on non-GET; `get_current_user` reading hashed session cookie (sliding 8h/24h max, A-25).
6. Strict base schema (`extra="forbid"`) used by all schemas.
7. Audit service `record(actor, action, target, detail, acting_for=None)` with an allow-list of detail keys that rejects forbidden fields (note, reason, token, password, sick type).
8. Logging filter that scrubs the same keys.
9. `/healthz` (`SELECT 1`, `{status}` only).
10. CI: ruff, mypy, pytest against a Postgres service.

## Risks and dependencies

- Q5 gate may fail → hosting redesign (C-16). Free-tier Supabase pooler may not support some features (prepared statements) → test the pooled URL in CI/staging.
- Role-level grants (no UPDATE/DELETE) cannot be tested on a superuser connection; tests must connect as the restricted app role.
- A-25 (cookie `Secure` in HTTP dev) and A-1 (layout) are unresolved.

| Criterion | Test |
|---|---|

| R29d | response headers asserted; forced exception returns problem+json without trace |
| R30 append-only | UPDATE/DELETE as app role on `audit_log` fails |
| R30 no secrets | audit.record with forbidden key raises; log scrub test with note/token strings |
