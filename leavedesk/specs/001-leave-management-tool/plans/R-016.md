# Plan 12: R16 cancel own Pending request

Phase P1. Depends on: 10. Blocks: 15, 16.

## Requirements and acceptance criteria

- **R16**: owner cancels own Pending request after confirmation → Cancelled, reserved days released, approver notified; Approved/Rejected/Cancelled cannot be cancelled by the employee (API 403, no UI button).

Endpoint #12 (`POST /requests/{id}/cancel`) is created here with the owner path; the HR path is plan 15. The shared cancel service is built so plan 15 adds only a branch.

Modify: `app/modules/requests/router.py`, `service.py`, `repository.py` (guarded UPDATE with `version` and expected status; set `is_active=false` on day rows).
Delete: none.

## Steps

1. Tests first: owner/non-owner/status matrix, stale version, double cancel.
2. Guarded update: `UPDATE … WHERE id AND version AND status='pending'`; zero rows → 409.
3. Same transaction: day rows inactive, audit (`cancel`, no reason text), outbox + notification to assigned approver (A-14 for HR queue).
4. Non-owner or non-Pending by employee → 403 per spec (A-4 note: HR branch deferred).
5. UI: cancel only on Pending; confirmation names the dates, default focus "Keep".
