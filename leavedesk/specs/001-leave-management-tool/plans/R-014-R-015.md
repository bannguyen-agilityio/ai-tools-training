# Plan 11: R14 notice rules + R15 Sick exemption and backdating

Phase P1. Depends on: 10. Blocks: none (but required for go-live).

## Requirements and acceptance criteria

- **R14**: single-day Annual/Unpaid starting in less than 1 day → rejected (hard block); more than 5 working days starting sooner than 1 week → warning to employee and approver, still submittable; 2–5 working days: no notice rule; measured in calendar days from submission in `COMPANY_TZ`.
- **R15**: Sick exempt from notice; employee may enter Sick up to 7 days back; older dates only by HR on the employee's behalf with a reason, audited.

Endpoint #17 (`POST /hr/requests`) belongs here. `notice_warning` is stored on the request and shown to the approver in plan 13's UI (the field exists; display is added here on the request detail).

## Files

Create: `app/modules/requests/notice.py` (pure `notice_check(leave_type, start, working_days, now)`); `app/modules/requests/hr_router.py`, `hr_service.py`; frontend warning banners in `NewRequest`, HR "Enter leave" form; `tests/requests/test_notice.py`, `test_sick.py`, `test_hr_entry.py`.
Modify: `app/modules/requests/rules.py` (plug in notice and `allow_backdate_days` from `leave_type`), `routing.py` if HR-entered requests reuse it.
Delete: none.

## Steps

1. Tests first with a frozen clock around midnight in `Asia/Ho_Chi_Minh` and UTC.
2. Implement `notice_check` returning block / warning / ok.
3. Wire block (422) and warning flag into submit and preview.
4. Sick: allow start ≥ today − 7; older → 422 for employees.
5. HR entry endpoint: body adds `employee_id` and required `entry_reason`; sets `entered_by`/`entry_reason`; audit; created `pending` per normal route.
6. UI: warning shown to employee before submit and on approver detail; HR form.
