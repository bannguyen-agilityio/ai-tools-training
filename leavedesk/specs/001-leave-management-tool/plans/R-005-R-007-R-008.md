# Plan 05: R5 leave types, R7 carry-over/expiry, R8 Sick no carry-over (balance engine)

Phase P1. Depends on: 01. Blocks: 07, 08, 09, 10.

Platform: the rollover/expiry cron caller uses the reusable `job.yml` from plan 00 (`R-platform.md`); this plan adds only the job module and its caller.

## Requirements and acceptance criteria

- **R5**: full-year employee Annual 12, Sick 7, Unpaid no limit/no balance; at most 6 Annual days carry over at year end.
- **R7**: 4 unused on 31 Dec 2026 → carry 4, expires 31 Dec 2027; 9 unused → carry 6, lose 3; carried days consumed first; expired carried days stop counting and the expiry is recorded as an entry; no re-carrying.
- **R8**: unused Sick days never carry over.

Core artefact: the pure function `compute_balance(entries, days, today)`, the only place balance rules live. The leave-request tables arrive in plan 06; here `days` is a plain input list, so the function is tested with fixtures.

## Files

Create: `app/modules/balances/{models,repository,service,schemas,router,dependencies}.py`; `app/modules/balances/compute.py` (pure, no DB); `app/jobs/rollover.py`, `app/jobs/expire_carry.py`; migrations for `leave_type` (+seed), `balance_entry` (CHECKs, idempotency key, grants: no UPDATE/DELETE); `tests/balances/{test_compute,test_rollover,test_expire,test_ledger_append_only}.py`; CI scheduled workflows.
Modify: none. Delete: none.

## Steps

1. Tests first: table-driven cases for `compute_balance` (carried-first, cap, expiry, half days, per-year, Pending reservation, multiple entry kinds).
2. `leave_type` seed and `balance_entry` table per §5.1 (0.5 steps, `reason` required for adjustment, signed days).
3. Implement `compute_balance` with entitlement/carried/used/reserved/available and carried-first consumption by leave date vs `expires_on`.
4. Repository: append-only writes with idempotency key conflict handling.
5. `rollover`: per active employee, entitlement rows for new year and `carry_over = min(6, unused current-year entitlement)`; key `rollover:<year>:<employee_id>`; Sick never carries.
6. `expire_carry`: write `expiry` entries once.
7. CLI entrypoints `python -m app.jobs.<name>`; scheduled CI jobs.

## Risks and dependencies

- A-7: "unused" is undefined for Pending reservations and late edits at year end; the formula must be agreed before step 5.
- Whole-system correctness hinges on this plan ("no balance corrections"): reviewers should check against §5.4 line by line.
- Compute used/reserved needs `leave_request_day` (plan 06): integration tests for used/reserved land in plan 09.
- Jobs run in CI with a production `DATABASE_URL`: secret handling per CLAUDE.md.
