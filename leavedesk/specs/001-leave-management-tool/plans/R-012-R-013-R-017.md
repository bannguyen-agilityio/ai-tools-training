# Plan 10: R12 create request, R13 validation/overlap, R17 routing

Phase P1. Depends on: 06 (day expansion, tables), 07 (employees/managers), 09 (sufficiency), 03 (emit). Blocks: 11–18.

## Requirements and acceptance criteria

- **R12**: active employee picks type, dates, Full/Morning/Afternoon, optional note → Pending request with computed working days; half-day counts 0.5; multi-day may start `pm` and end `am` (Q7).
- **R13**: end before start refused inline; overlap with own Pending/Approved refused naming the conflict (am+pm same date do not clash); past start for Annual/Unpaid refused (Sick in plan 11).
- **R17**: employee's request assigned to the direct manager who is emailed; a manager's request goes to HR (queue `hr`) and HR is emailed; nobody approves their own request (enforced in plan 13, with the DB CHECK here).

Endpoints #9 (`POST /requests/preview`), #10 (`POST /requests`), #11 (`GET /me/requests`, `GET /requests/{id}`). Notice rules and Sick backdating are plan 11; the HR-queue `deputy` route is plan 17.

## Steps

1. Tests first: concurrency (two simultaneous submits), overlap, half-day shapes, routing matrix, redaction.
2. Strict schemas; DB checks from §5.2 already migrated in plan 06.
3. Submit transaction: lock employee row `FOR UPDATE`, expand days, run rules, insert request + day rows (unique index → 409), audit, outbox, notification; return `201` + `Location`.
4. Preview endpoint reuses the same pipeline, writes nothing; returns days, per-year split, balance after, errors.
5. Routing function: employee → `manager_id`; manager → `queue=hr`, `assigned_to` null; edge cases per A-10 stop and ask.
6. Redaction layer for GET responses (note and Sick type visible only to owner/assigned/covering approver/HR).
7. UI New request / My requests / detail; cancel button added in plan 12.
