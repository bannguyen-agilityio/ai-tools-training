# Plan 14: R20 cover for an absent manager

Phase P1. Depends on: 13. Blocks: none.

## Requirements and acceptance criteria

- **R20**: another manager opens "Approve on behalf" and can see/decide the absent manager's Pending requests; every cover decision records both actual approver and direct manager in the audit log and emails the direct manager. Absence is not tracked (Q9): any manager can cover via the "On behalf of" tab, audit and email are the only controls.

Endpoint #13 `scope=cover`; #14/#15 accept `on_behalf_of`.

## Files

Create: `app/modules/approvals/cover.py`; template `approved_on_behalf` (and a reject-on-behalf variant); frontend "On behalf of" tab in Approvals; `tests/approvals/test_cover.py`.
Modify: `approvals/authz.py` (`can_decide` cover branch), `router.py`, `service.py`, audit writer (`acting_for_id`), `redaction.py`.
Delete: none.

## Steps

1. Tests first: who may cover, audit shape, email to direct manager, redaction for cover viewers.
2. `scope=cover` list: other managers' reports' Pending items, excluding the caller's own reports and own requests.
3. Decision with `on_behalf_of=<direct manager id>`: validate it equals the request's assigned manager; set `decided_on_behalf_of`, `decided_by`.
4. Audit with `acting_for_id`; outbox + notification to the direct manager (no Sick type, no reason).
5. UI tab separate from the default list, with an explicit "You are deciding for <name>" statement.

## Risks and dependencies

- C-5: broad permission by design; only the audit/email controls it. Ensure the default list never shows cover items.
- A-13: whether cover managers see the note/Sick type "only while deciding".
- Should cover apply to rejected-with-reason notification? Reject-on-behalf email to the direct manager must omit the reason (privacy rule).
- Who covers HR-queue requests is plan 17, not here.
