# Plan 02: R31 mobile, accessibility and UX standard (frontend foundation)

Phase P1. Depends on: plan 01 (only for serving `dist` at `/`). Can run in parallel with 03/04.

## Requirements and acceptance criteria

- **R31**: (a) 360 px, no horizontal scroll, ≥ 44 px targets, request/approve usable on phone; (b) visible labels, announced and linked errors, colour never the only signal, WCAG 2.1 AA contrast; (c) unambiguous dates ("Mon 2 Nov 2026") in display and pickers; (d) forms keep input, say what/how to fix, focus the first error; (e) destructive actions confirm with default focus on "Keep".

This plan builds the shared pieces that every later UI slice must reuse; later plans prove R31 on their own screens.

## Files

Create: `frontend/package.json`, `vite.config.ts`, `tsconfig.json`, `eslint` config (with `jsx-a11y`); `frontend/src/main.tsx`, `App.tsx`, `routes.tsx`; `src/api/{client,problem}.ts` (fetch wrapper: CSRF header, 401 → sign-in preserving return path (R2), problem+json parsing); `src/ui/{Button,Field,TextField,DateField,Select,FormError,ErrorSummary,ConfirmDialog,Layout,Nav,Toast}.tsx`; `src/lib/dates.ts` (format/parse "Ddd D Mon YYYY", `COMPANY_TZ`); `src/styles/` (tokens, mobile-first); `src/ui/*.test.tsx`; `e2e/a11y.spec.ts` (Playwright + axe at 360 px); `app/spa.py` (serve `frontend/dist`, SPA fallback for non-`/api` paths).
Modify: `app/main.py` (mount SPA), CI (add frontend jobs and build).
Delete: none.

## Steps

1. Tests first: component tests for Field (label/error linking), ConfirmDialog (default focus "Keep"), date formatter, `useFormFocusFirstError`.
2. Vite + TS + Router + TanStack Query + RHF + Zod scaffold.
3. Design tokens with AA-checked colours; status shown by text/icon plus colour.
4. Shared form components and focus-first-error helper.
5. `ConfirmDialog` naming the exact consequence; default focus "Keep".
6. Date utilities and picker wrapper (same format in/out; ISO on the wire).
7. API client with 401 handling and CSRF.
8. SPA fallback in FastAPI; CI builds frontend then backend.
9. Playwright + axe smoke at 360 px on the shell and a sample form.

## Risks and dependencies

- Native date inputs show locale-dependent formats, which conflicts with R31(c); a custom/wrapped picker costs time (A-23: UI language also unspecified).
- CSP from plan 01 may block Vite-injected inline styles; coordinate nonce/hashing.
- Axe catches only part of AA; keep a manual checklist in the PR.

## Tests proving each criterion

| Criterion | Test |
|---|---|
| R31a | Playwright at 360×640: no `scrollWidth > clientWidth`; computed min target size ≥ 44 px for buttons/links/inputs |
| R31b | RTL: every input has an accessible name; error has `aria-describedby`/`aria-invalid`; axe has no AA violations |
| R31c | unit: `formatDate(2026-11-02)` → "Mon 2 Nov 2026"; picker round-trip |
| R31d | RTL: invalid submit retains values, focus lands on first invalid field, summary announced |
| R31e | RTL: dialog opens with focus on "Keep"; Escape keeps |

## Definition of done

- Shared components documented in a short `frontend/README`; every component test green; axe clean on the shell; SPA served by FastAPI on staging; later plans can import the primitives without copying.
