# Plan 19: R32 performance, R33 backup/restore, R34 retention

Phase P1. Depends on: 01 to start (backup, keep-alive); finish after 18 (perf on real endpoints). Blocks: go-live sign-off.

## Requirements and acceptance criteria

- **R32**: 250 users and 150 requests/month: p95 server time < 500 ms on the target host.
- **R33**: nightly backup; documented restore drill restores in under 30 minutes.
- **R34**: deactivated employee's history kept 7 years, accessible only to HR.
- Related jobs from §5.6: `backup`, `keepalive` (free-tier pause mitigation), `purge`.

## Files

Create: `app/jobs/backup.py` (or script wrapping `pg_dump`), `.github/workflows/{backup,keepalive}.yml`; `docs/runbooks/restore-drill.md`; `tests/perf/{seed.py,test_p95.py}` (or `scripts/loadtest`); `tests/retention/test_hr_only_history.py`; index review migration.
Modify: queries flagged by perf run.
Delete: none.

## Steps

1. Tests first: retention access test; perf harness that seeds 250 users and ~12 months of requests.
2. Backup job: `pg_dump` to private storage (target undefined, A-17), 30-day retention.
3. Keep-alive workflow hitting `/healthz`.
4. Perf run against staging (not local); fix indexes and N+1s.
5. Restore drill into a scratch database; time it; document steps.
6. Retention: confirm deactivated users' history is HR-only on every read path (requests, calendar, reports); do not add deletion.

## Risks and dependencies

- A-15: R34 has no mechanism (purge after 7 years? `audit_log` is append-only), A-16: no measurement method, A-17: storage target and secrets unspecified.
- Free-tier Supabase backups and pooled-connection limits (C-16, Q13); personal-account ownership is an accepted risk.
- Backup dump contains all HR data: storage must be private and encrypted; access list undefined.
